## 拖动卡死（2026-10-13 找到根因并修复）

- 现象：拖动表或便签松手时，页面偶尔停止响应（之前以为好了，其实是偶发）。
- 复现：把便签或表拖到画布边缘、停留（触发自动平移）再松手，约 5 次里卡 1 次。
- 根因：保存拖动后位置的代码写在了 React 的状态更新函数里。React 有时会重跑这种函数，每重跑一次就再保存一次，保存又触发重建，形成无限循环（约 4.6 万次后被暂停抓到），页面因此卡死。
- 修复：状态更新函数里只做纯计算，拖动结束后由副作用保存一次。新增 `e2e/scenarios/drag-stress.mjs`（每次 32 次边缘拖动）防止复发。

## 图形化编辑（2026-10-12 新增）

不写代码也能完成建表和建关联，左边的 DBML 会同步改写（只改动到的部分，注释和格式保留）：

- **建表**：画布左上角「表」按钮，或双击画布空白处。新表自动打开右侧属性面板，名称框已选中，直接输入表名。
- **表属性**：名称（可写 `schema.表名`）、备注、表头颜色、删除表。改表名时关联、分组、位置都会跟着改。
- **字段**：新增、改名、改类型（有常用类型和枚举的下拉提示）、PK / NN（非空）/ UQ（唯一）/ AI（自增）开关、默认值、备注、上移下移、删除。改字段名时关联和索引跟着改。
- **索引**：勾选字段新建（可设唯一），切换唯一 / 主键，删除。
- **关联**：鼠标移到字段上，两侧出现蓝色圆点，拖到另一张表的字段（或表头）上松开即建立关联；从主键拖到普通字段会自动反向。点连线打开关联面板：多对一 / 一对多 / 一对一 / 多对多、删除时 / 更新时动作、交换两端、删除关联。
- **枚举**：工具栏「枚举」，新建、改名（用到它的字段类型跟着改）、增删值、值备注、删除。
- **便签**：工具栏「便签」，改名、内容、颜色、删除。
- **分组**：选中几张表（⌘ 点选或 Shift 框选）后点「分组」，面板里改名、颜色、备注、勾选成员、删除分组（保留表）。
- **删除 / 撤销**：选中表或便签按 Delete 删除；工具栏的撤销 / 重做按钮，或在画布上按 ⌘Z / ⇧⌘Z。
- **表别名**：表面板「别名」。
- **复合（多字段）关联、关联命名**：表面板「关联关系 → + 关联」，选被引用的表，逐对选字段（可加多对），选类型、填名称。关联面板里还能改名称、改颜色（连线按颜色显示）、增删字段对。
- **索引细节**：索引右侧 ⋯ 展开，可改字段、名称、类型（btree / hash）、备注；新建时可加表达式索引（如 `lower(email)`）。
- **检查约束**：字段 ⋯ 里的「检查约束」，以及表面板的「检查约束」区（表达式 + 可选名称）。
- **表模板（TablePartial）**：工具栏「模板」，新建、改名、备注、表头颜色，模板里的字段 / 索引 / 检查约束和表一样编辑；表面板「模板」一栏引入或移除（`~模板名`）。来自模板的字段在表里只读，改模板即可。
- **示例数据（Records）**：表面板「示例数据」，表格里直接填，空格子为 null；可加行、删行、删整块。改表名、改字段名、删字段时示例数据跟着改。导出 SQL 时生成 INSERT。
- **项目设置（Project）**：工具栏「项目」，名称、目标数据库、说明；项目块里其他自定义条目会保留。
- 属性面板打开时单击别的表会切换到那张表；Esc 或 × 关闭。
- 文档有语法错误时图形编辑会提示先修正错误。

- **依赖（Dep，数据血缘）**：工具栏把「关联 / 依赖」切到「依赖」，从字段圆点拖到另一字段建字段级依赖，从表头圆点拖到另一张表建表级依赖；画布上画成带箭头的彩色虚线。点依赖线打开面板：名称、颜色、备注、多条依赖线、自定义属性、删除。表面板也有「依赖关系」区。
- **停用关联（inactive）**：关联面板勾选，画布上显示为淡色虚线。
- **自定义属性（Metadata）**：表、字段（字段 ⋯）、分组、便签、项目、依赖都能加 `键: 值` 属性。
- **示例数据 example 标记**：示例数据下方勾选。
- **模板注入的位置**：表面板模板标签上的 ↑↓，决定模板字段出现在表里的位置。
- **图视图（DiagramView）**：工具栏「视图」，新建视图（新建后自动显示），选「全部表」或勾选表 / 整个分组 / 整个 schema，便签可选不显示 / 全部 / 勾选；改名、删除。画布底部工具栏可在「全部内容」和各视图之间切换，画布只画该视图里的表、它们之间的连线、分组和便签，顶部提示隐藏了几张表。显示某个视图时新建的表 / 便签会自动加入该视图；改名或删除表、分组、便签时视图跟着改。（这一项以前连写代码也不生效——程序之前根本不读 DiagramView，现在支持了。）

顺带修的问题：
- 点表格会把焦点给编辑器，之后按 Delete 会删掉编辑器里被选中的那一行代码 —— 现在点表只滚动代码、不抢焦点。
- 字段改名后连线可能找不到锚点（React Flow 不会重新测量），已修。
- 画布偶尔被浏览器横向滚动，导致左侧工具栏被遮住一截，已修。
- 传给 React Flow 的回调每次都换新，导致打字时多余开销；固定后 60 张表的图打字耗时比优化前还低（约 120 ms / 28 次按键，之前 164 ms）。

## 拖动性能（2026-10-13 第二轮，两项都已做，未提交）

测量：60 张表、115 条连线、2 倍屏、CPU 降速 4 倍，每次拖 90 步；单表 / 分组 / 多选，三种缩放。脚本已存进仓库 `scripts/perf/`（见下方「下次从这里接着做」）。

1. **去掉连线高亮的无限「流动虚线」动画**，改成静态的加粗蓝色实线。这个动画在表被悬停或选中期间每帧重画、重新合成整张画布；鼠标停在表上不动时每 3 秒白耗约 190 ms，改后为 0。
2. **去掉约 3,100 个隐形连接点组件**。以前每个字段有 4 个 React Flow `<Handle>`，每个都订阅状态，拖动每帧逐个检查。现在锚点是不订阅任何东西的普通元素（React Flow 照样能测量它们的位置），可拖的蓝色圆点只在鼠标所在的那一行出现。

| 拖动场景（主线程总耗时 / 其中脚本） | 改前 | 第 1 项后 | 两项后 |
|---|---|---|---|
| 单表，缩放 0.45 | 4.1–4.3 s | 1.9 s / 0.7 s | 0.9–1.0 s / 0.26–0.29 s |
| 单表，100% | 3.9 s | 2.4 s / 1.3 s | 0.83–0.90 s / 0.33–0.36 s |
| 分组 | 2.7 s | 2.6 s / 0.73 s | 1.3–1.4 s / 0.35 s |
| 多选 | 4.5 s | 3.0 s / 1.4 s | 1.24–1.28 s / 0.47 s |

掉帧（>17 ms 的帧）从每次几帧到几十帧降到 0–3 帧（缩到最小时拖分组仍有 6–8 帧）；单表拖动的合成（Layerize）1.4 s → 0.21 s。画面和拖线建关联 / 依赖的手感不变。

## 性能优化（2026-10-12 第一轮）

测量方法：Playwright 加载扩展，在示例图和一张 60 张表的图上分别跑悬停、拖动、打字、缩放，记录脚本耗时、帧间隔和「停止打字到图更新」的延迟；另用 CPU 降速 4 倍模拟慢机器。

找到的瓶颈和改法：

| 问题 | 改法 | 60 张表，正常速度：前 → 后 |
|---|---|---|
| 悬停任何东西，所有表格和连线都重新渲染（高亮状态放在一个 Context 里，每次变化全员更新） | 高亮改成独立的小仓库 `HighlightStore`，每个表格、字段行、连线只订阅自己要显示的那一个值 | 悬停脚本耗时 242 → 98 ms |
| 拖动时每一帧所有连线对象都重建，选中集合每帧都是新对象，又触发全员更新 | 没变的节点和连线沿用原对象；选中集合只在真正变化时推送 | 拖动脚本耗时 47 → 19 ms |
| 打字后要等 250 ms 才开始解析（解析本身只要 10–60 ms） | 等待缩短到 100 ms；错误提示多等 400 ms 再显示，避免打字中途反复闪红 | 停止打字到图更新 约 200 → 约 65 ms |
| 每次解析都生成全新的模型，所有表格都要重新渲染 | `reuseUnchanged`：没变的表、关系、分组沿用上一次的对象 | 只重绘改动的部分 |

代价：语法错误的提示比以前晚出现约 250 ms（约 0.25 s → 0.5 s）。

示例图（3 张表）改前改后都在 120 帧以内，没有可感知的差别。

还剩下的、这一轮没动的：

- 首次打开约 0.5–0.9 s，主要是后台线程加载 16 MB 的 `@dbml/core`。这个库打包成单个文件，拆不开；要再快只能改用 `@dbml/parse` 自己拼模型，工作量大，暂不做。
- 大图在慢机器（CPU 降速 4 倍）上悬停仍有掉帧，耗时主要在浏览器自身的命中检测和重绘，不在我们的脚本里。
