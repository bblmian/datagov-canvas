# 图形编辑覆盖表

目的：证明「凡是 DBML 代码能写的，图形界面都能做」。两道自动检查：

1. `npm test` 里的 `src/dbml/coverage.test.ts`：语法里的每一项都对应到存在的编辑操作。
2. `npm run e2e -- grammar-coverage`（`e2e/scenarios/grammar-coverage.mjs`）：在真实扩展里**只通过画布和属性面板**逐项操作，每一步核对生成的 DBML；运行时从语法文件读出全部 17 种元素和 19 种设置，只要有一项没被图形操作覆盖就失败。当前结果：36 / 36。

清单不是凭印象列的，而是直接取自所装 DBML 语法（`@dbml/parse`）里的两个枚举：**元素种类**和**设置项**。`src/dbml/coverage.test.ts` 会读取这两个枚举，要求每一项都对应到 `src/dbml/edit.ts` 里存在的编辑操作；以后升级库、语法多出新关键字时，这个测试会失败，提醒补上。

最后核对：2026-10-12，`@dbml/core` 10.2.0（内含 `@dbml/parse`）。

## 联动（改一处，引用它的地方跟着改，保证文档始终有效）

改表名 / 字段名，或删除表 / 字段 / 分组 / 便签时，会自动同步：关联（独立的和内联的）、依赖（块和内联）、分组成员、索引、示例数据的列、视图里的列表、自定义属性块的目标名、模板注入。每种情况都有单元测试。

## 独立审查（2026-10-13）

另派一个没看过本表的审查者，从解析器源码重新梳理「代码能写的一切」，再逐项对照界面。它找出的问题已全部修复，并有专门的端到端场景 `audit-fixes` 逐项验证：

| 审查发现 | 修复 |
|---|---|
| 索引类型只能选 btree / hash，`gin` 等显示为空 | 类型改为可自由填写（带常用类型提示） |
| 字段、索引、枚举值、模板的备注不能多行 | 都改为多行输入框 |
| 示例数据不能选部分字段，已有数据块不能增减字段 | 新建时勾选字段；表头可去掉字段、添加字段 |
| 改一个格子会把整块重写：`'123'` 变数字、`'true'` 变布尔、枚举值丢失 | 只改被编辑的格子，其余保持原样；被编辑的格子保持原类型 |
| 便签不能设 `color: none` | 颜色里加「无填充」，画布上显示为透明虚线框 |
| 一个字段的多个检查约束，编辑时会丢掉第二个以后的 | 字段 ⋯ 里是检查约束列表，全部保留、可增删 |
| 模板里的字段不能带关联和自定义设置 | 模板字段 ⋯ 里有「引用」和「自定义属性」；由模板产生的关联在关联面板里会提示到模板去改 |
| 默认值的类型只能靠手写引号 / 反引号 | 默认值前有类型选择：文本、数字、布尔、null、表达式 |
| 新填的示例数据格子要靠手写引号区分类型 | 新格子按字段类型决定：数字列写数字、布尔列写布尔、枚举列写 `枚举.值`（只输值名也行）、其他（含日期）写文本；已有格子保持原类型 |
| 依赖的自定义值都写成字符串 | 数字、布尔、null、文本各自保持（直接读源码，因为解析器把 `true` 和 `'true'` 混为一谈） |
| 表自己的字段不能改名成与模板字段同名（覆盖） | 允许，表自己的字段覆盖模板字段 |
| 枚举值不能调顺序 | 加了上移 / 下移 |

审查同时证实：`use … from` 在单文件里无法解析，依赖的多字段元组 `a.(x,y) -> b.p` 在本版本里绑定失败，均不属于可用功能。

修复过程中又从语法里发现一条限制：**一张表只能有一块示例数据**。界面在已有数据时不再提供「+ 示例数据」，引擎也会拒绝。

另外，反复运行这些场景时抓到一个与语法无关的真实 bug：表格新出现时，若节点重建恰好和 React Flow 的测量同时发生，这张表的所有连线会一直不显示。已修复（约 1/7 的失败率 → 连续 12 次全过）。

## 语法本身的限制（图形界面照语法执行，并给出提示）

- 表至少要有一个字段：删最后一个字段时会提示。
- 同一个依赖里的各条线必须指向同一张下游表，并且都是表级或都是字段级；两个依赖不能连接完全相同的两端：违反时会提示，不会写出无效 DBML。
- 关联名和依赖名不能带 schema 前缀。
- 一张表只能有一块示例数据（Records）。
- `Metadata` 只能指向表、表里的字段（包括来自模板的字段）、分组、便签；不能指向模板本身或模板里的字段，模板字段的自定义属性写在字段的设置里。

## 端到端测试（`npm run e2e`，在真实扩展里只用鼠标和面板）

`grammar-coverage` 之外还有五套场景：

- `build-schema`：建表、字段、拖线关联、改关联类型和动作、枚举、索引、便签、分组、改名、Delete 删除和 ⌘Z 撤销，最后导出 PostgreSQL。
- `advanced`：项目设置、模板（含上下移动注入）、别名、检查约束、索引细节、表达式索引、多字段命名关联、关联颜色、示例数据，最后导出 PostgreSQL（含 INSERT、CHECK、索引、外键）。
- `views`：图视图：新建、勾选表、切换、新建表自动加入视图、改名同步、删除。
- `audit-fixes`：独立审查发现的每一项（见上表）。
- `lineage`：依赖（字段级和表头拖线的表级）、依赖编辑、停用关联、自定义属性（表、字段、便签、项目、依赖）、example 示例数据、改名后全部同步。
